# 美术素材清单（第一次：主角 / 史莱姆 / 城市 / 地牢）

## 0. 现在的情况（重要）
- 工程里**目前没有任何外部美术文件**：所有画面都是代码用 `Texture2D` 现场画的像素图（`Assets\Scripts\View\PixelArt.cs`），由 `Assets\Scripts\View\SpriteLibrary.cs` 缓存成 `Sprite`（`Sprite.Create(tex, rect, pivot, pixelsPerUnit: 16, 0, SpriteMeshType.FullRect)`）。
- 场景（地板 / 墙 / 门 / 梯子 / 碎石）是 `Assets\Scripts\View\MeshBuilder.cs` + `Assets\Scripts\View\RoomView.cs` 生成的方块网格，材质由 `Assets\Scripts\View\MaterialLibrary.cs` 提供（依次尝试 `Standard` → `Universal Render Pipeline/Lit` → `Legacy Shaders/Diffuse` → `Unlit/Color` → `Sprites/Default`）。
- 所以：**现在就打开就能玩**，不用等美术；接入真实素材时**不用改玩法逻辑**，只要把 `SpriteLibrary` / `MaterialLibrary` 的取图实现换成"读你的图片"。

## 1. 通用导入设置（每一张像素图都按这个设）
| 项目 | 值 |
| --- | --- |
| Texture Type | Sprite (2D and UI) |
| Sprite Mode | Single |
| Pixels Per Unit | **16**（1 个方格 = 16 像素，全局只有这一个刻度） |
| Filter Mode | **Point (no filter)** |
| Compression | **None** |
| Generate Mip Maps | 关 |
| Wrap Mode | Clamp |
| Max Size | 512 以上 |
| 透明 | 用 Alpha 通道（不要用纯黑/纯色背景） |

## 2. 主角（像素小人，8 方向）

方向顺序必须和代码里的差分下标一致（`DungeonCity.Sim.MoveInput.SpriteIndex`）：

| dirIndex | 方向 | 键位 |
| --- | --- | --- |
| 0 | 下 | S |
| 1 | 左下 | S+A |
| 2 | 左 | A |
| 3 | 左上 | W+A |
| 4 | 上 | W |
| 5 | 右上 | W+D |
| 6 | 右 | D |
| 7 | 右下 | S+D |

| 素材 | 现用尺寸 | 帧数 | Pivot | 代码位置 | 用途 |
| --- | --- | --- | --- | --- | --- |
| player_{dir}_{frame} | 16×16 | frame 0 静止 / 1、2 行走 | (0.5, 0) | `SpriteLibrary.Player(dir, frame)` | 主角本体（行走 7 帧/秒） |
| player_hurt_{dir}_{frame} | 16×16 | 同上，可选 | (0.5, 0) | `SpriteLibrary.PlayerHurtFrame(dir, frame)` | 受击变红（现在是用染色副本做的，单独出图可更精细） |
| player_ghost_{dir}_{frame} | 16×16 | 同 Player | (0.5, 0) | `SpriteLibrary.PlayerGhost(dir, frame)` | 冲刺残影（现在 = 淡蓝半透明染色，可不单独出图） |

## 7. 接入步骤（不改玩法逻辑）
1. 把图片按上表的命名放进工程，例如 `Assets\Art\Player\`、`Assets\Art\Slime\`、`Assets\Art\Env\`、`Assets\Art\Fx\`。
2. 在 `Assets\Scripts\View\SpriteLibrary.cs` 里把每个工厂方法（`Player` / `Sword` / `Slime` …）从"调 `PixelArt` 生成"改成"载入你的 Sprite"，例如 `Resources.Load<Sprite>($"Art/Player/player_{dir}_{frame}")` 或 `AssetDatabase.LoadAssetAtPath<Sprite>(...)`（编辑器用）。键名与 Pivot 必须保持上表一致，其它代码不用动。
3. 场景贴图：在 `Assets\Scripts\View\MaterialLibrary.cs` 里把 `Floor/Wall/Door/Ladder/ForTile` 换成"贴图材质"（`material.mainTexture = 你的贴图`，`mainTextureScale` 按 16px/格 设）。

## 10. 补充：文档第三次增量（跳跃 / 背包 / 史莱姆清）新增的素材需求

- **跳跃姿势帧（新增）**：`SpriteLibrary.PlayerJump(dirIndex)` → 键 `pjump_{dirIndex}`，8 方向 × 1 帧、16×16px、**Pivot (0.5, 0)**；命名建议 `player_jump_{dir}.png`。
  dirIndex 与方向对应关系同第 2 节（0 下 / 1 左下 / 2 左 / 3 左上 / 4 上 / 5 右上 / 6 右 / 7 右下）。现在用程序化版本（两腿抬起并左右分开，`PixelArt.DrawJumpLegs`）。
- **跳跃的"腿与阴影分开"不需要新图**：阴影沿用 `SpriteLibrary.Shadow()`（16×7，Pivot 0.5,0.5）；浮空时整体上移（`PlayerView` 把广告牌子整体抬 `AirHeight` 格），影子留在原地并缩到 72%。
- **史莱姆清图标（新增）**：`SpriteLibrary.SlimeJelly()` → 键 `slime_jelly`，**10×10px ≈ 0.6 格**、Pivot (0.5,0.5)；图案参考原神中的史莱姆清（青绿果冻、顶部高光、底部沉色、几个小气泡）。命名建议 `item_slime_jelly.png`。
- **掉落物微光**：复用 `SpriteLibrary.Blast()`（淡绿 (0.62,1,0.74,0.30)、order 6），不需要新图。
- **背包 UI**：目前是 HUD 里的一行文字（`背包：已用 n/50 格　物品列表`），没有格子图标；若要可视化 50 格背包，需要 `slot_cell.png`(26×26, Pivot 0.5,0.5) 与可选的 `slot_selected.png`(26×26)。
- **小地图（调试2-5）**：纯 UGUI 纯色格子 + 文字，不需要素材；若要皮肤需要 `minimap_frame.png`（约 156×116，Pivot 0.5,0.5）。
- **最小增量**：跳跃帧 8 张 + 史莱姆清 1 张 = **9 张**（原最小集合 29 张 → 38 张）。

## 11. 补充：文档第四次反馈（调试3）对素材的影响

- **背包格子界面（已接入）**：`Assets\Scripts\UI\InventoryUI.cs`，5 行 × 10 列 = 50 格，格子 **44×44px**、间距 6px；目前是纯色 UGUI 方块 + 图标 + 数量文字。
  - 美化用（可选）：`ui_slot_cell.png`（44×44、九宫格边框、Pivot 0.5,0.5）与 `ui_slot_selected.png`。
  - 物品图标：现在只有史莱姆清用 `SpriteLibrary.SlimeJelly()`，其它物品是染色方块；接入点时按物品名查表即可（给 `SpriteLibrary` 加一个 `ItemIcon(name)`）。
- **冲刺残影（反馈 5 已改成"身后跟随的分身"）**：**不需要新图**，复用 `SpriteLibrary.PlayerGhost(dir, frame)`（程序化剪影）。若想要更精致的残影，可给一组 `player_ghost_{dir}.png`（16×16、单色半透明、Pivot (0.5, 0)）。

- **最小增量**：背包图标 1 张（+ 可选格子底图/选中框 2 张）；冲刺残影、跳跃影子和横线修复都不需要新图。最小集合仍是 29 张 + 跳跃帧 8 张 + 史莱姆清 1 张 + 背包图标 1 张 = **39 张**。
