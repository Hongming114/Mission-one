## 1. 世界与三层矩阵

| 层级 | 含义 | 数据 |
| --- | --- | --- |
| M | 当前所在世界 | 城市 = 1，地牢 = 2 |
| I 类矩阵 | 大地图房间分布，每个数字 = 一个房间类型 | 0 = 无房间，1 = 标准房间·城市，2 = 标准房间·地牢 |
| II 类矩阵 | 房间内每个格子的**物理类型** | 0 地板，1 墙，2 门，3 梯子（城市/地牢共用一个编码，外观不同） |
| III 类矩阵 | 与 II 同尺寸的**功能矩阵** | 1 = 普通可达，0 = 不可达，2.1 = 传送到相邻房间，2.2 = 传送到另一个世界 |

II → III 的对应关系在 `Assets\Scripts\Gen\RoomBuilder.cs` 的 `FuncOfTile(int)` 里，是唯一权威：

| II 值 | 城市房间 | 地牢房间 | III 功能 |
| --- | --- | --- | --- |
| 0 | 白色光滑地板 | 灰色粗糙地板 | 1 普通可达 |
| 1 | 墙 | 墙 | 0 不可达 |
| 2 | 门（只开在边界墙的**正中间**） | 门 | 2.1 传送到相邻房间 |
| 3 | 地牢入口梯子（房间内部） | 城市入口梯子 | 2.2 传送到另一个世界 |

补充规则（自检器会强制检查）：
- 房间边界一圈只能是墙或门；门只出现在边界墙的中点，且必须与 I 类矩阵里该方位"有邻居"一致。
- 梯子只出现在房间内部，且**整个世界只有 1 个 II=3 的格子**。
- 出生格必须是普通可达格（III=1），既不是门格也不是梯子格。

## 3. 房间类型参数（`Assets\Scripts\Gen\WorldCatalog.cs`）

改地图形状、房间大小范围、装饰数量、颜色都在这一个文件里改。

| 参数 | 城市房间 | 地牢房间 |
| --- | --- | --- |
| 宽/高范围 | 10–15 × 10–15 | 10–15 × 10–15 |
| 四角立柱 | 有，每角 70% 概率、向内缩 2 格 | 无 |
| 碎石障碍 | 0 个 | 每房 3–9 个（避开门口 3×3 区域） |
| 中央十字通道 | 强制留空（keepCrossFree） | 强制留空 |
| 地板 | 白色光滑 (0.93,0.94,0.96)，5% 格子略深 | 灰色粗糙 (0.36,0.36,0.39)，30% 格子略深 |
| 墙 / 门 / 梯子色 | (0.56,0.61,0.72) / (0.87,0.68,0.30) / (0.30,0.62,0.52) | (0.24,0.22,0.21) / (0.56,0.43,0.22) / (0.35,0.66,0.78) |
| 墙高 | 1.2 | 1.4 |
| 房间间距（世界坐标） | 18 格 | 18 格 |

每个房间用**自己的**随机数序列（房间种子 = 世界种子、房间坐标混合而成），所以：世界种子一定 → 整张地图完全可复现；换一个世界种子 → 尺寸与内部布置整体重掷。

## 4. 生成流程（`Assets\Scripts\Gen\WorldGenerator.cs`）

1. 读 I 类矩阵，收集所有房间坐标。
2. 对每个房间看 I 类矩阵里的四个邻居，算出该开哪几个门（`ComputeDoors`）。
3. `RoomBuilder.Build` 生成房间：随机尺寸 → 边界墙 + 门 → 四角立柱/碎石等装饰 → `DeriveFunc` 写出 III 类矩阵。
4. **连通性保险**：如果加完石块后房间内部四连通被破坏，就按放置顺序从后往前把石块撤掉，直到恢复连通（保证"III 非 0 的格子一定互相走得到"）。
5. 门对（`LinkPortals`）：每对相邻房间记一条连接，门格坐标按各自房间尺寸取墙中点——所以左右两间房的门不一定在同一相对位置，靠记录配对而不是几何对齐。同一对房间只记一条（按 (y,x) 字典序去重）。
6. 出生房间、出生格：出生格取房间里离中心最近的普通可达格。
7. 梯子格：全世界唯一，取"离房间中心最近的可站立格"，并**避开出生格**（地牢里出生房间同时也是梯子房间，这一条是必须的）。
8. `WorldValidator.Validate` 自检；任何一条不通过就直接抛异常，不给"带病"的地图。

## 5. 传送与玩法

- 走到 **2.1 门格**：立刻移动到配对门格（可能跨房间），落脚点仍然是可走的格子。
- 走到 **2.2 梯子格**：切换世界（城市 ↔ 地牢），落点是目标世界唯一的梯子格。
- 玩法操作：主界面点「开始游戏」→ 空场景自动搭起世界（城市出生）；
  `W A S D` 或方向键走格子（一次一格）、`V` 调试用直接切世界、`R` 回到出生点、`F1` 开关 HUD。
- HUD 显示：M / 种子 / I 矩阵尺寸 / 房间数 / 当前房间 / 玩家坐标（II 与 III）/ 朝向与步数 / 房间距离统计 / 刷怪判定次数与倒计时 / 场上怪与上限 / 最近事件。
- 相机为斜视正交跟随（yaw 45°、pitch 52°），主角是方块小人。

## 6. 刷怪规则（v2，已实装）

参数（`Assets\Scripts\Core\WorldGenConfig.cs` 默认值）：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `monsterCellSampleRatio` | 0.10 | 每个符合距离条件的房间随机抽 floor(非不可达格数 × 10%) 个格子 |
| `monsterSpawnChanceP` | 0.02 | 抽样格逐格判定概率 |
| `monsterMinRoomDistance` | 2 | 只在离玩家房间距离 ≥ 2 的房间刷怪 |
| `monsterJudgeIntervalSeconds` | 60 | 判定周期 t |
| `monsterForceJudgeMaxCount` | 2 | 场上怪 ≤ 2 → 立即判定（不等 t） |
| `monsterForceJudgeMinInterval` | 5 | **本次自定的最小冷却**，避免每帧判定（待确认） |
| `monsterCapRoomsFactor` | 2 | 场上怪上限 = 2 × 房间数（地牢 7 房 → 14） |

判定流程：按周期（或怪太少时立即）取"离玩家房间距离 ≥ 2"的所有房间 → 每房随机抽 10%（向下取整）的格子 → 每格以 P=0.02 判定 → 判定成功且该格是普通可达格（III=1）就在那里生成一只 → 达到上限的判定算通过但不生成。

干跑结果（地牢 7 房）：连续 6 次判定共生成 3 只；抽样格子数 40 = Σ floor(可站立格 × 10%)（逐房核对一致）；上限测试（场上 14 只）判定照做、新增 0。

## 9. 验证情况

**A. dotnet 逻辑台架（已全部通过）**：`Tools\LogicCheck` 用最小 UnityEngine 桩把 `Assets\Scripts\Core`、`Assets\Scripts\Gen` 编译成控制台程序真实跑一遍，检查：
世界自检 0 条问题 / 出生格与梯子格（III=2.2、全世界唯一 1 个）/ 每房四连通 / 门格数 = 连接数×2 / 出生格能走到梯子格 / **所有可站立格都可达**（城市 1072 格、地牢 848 格全部可达）/ 房间距离表 / 刷怪规则（6 次判定、立即判定冷却、上限压制、抽样格子数逐房核对）/ 矩阵导出。
这一步查出并修掉了 4 个真实缺陷：
1. `RoomConnectivity.cs` 缺 `using UnityEngine;`（Unity 里会直接编译报错）。
2. `WorldGenerator.LinkPortals` 把每对相邻房间记了**两次**连接，导致门格数与连接数对不上，自检失败。
3. 自检器错误地禁止"房间内部出现梯子"，而梯子本来就该在房间内部（出生房间与梯子房间相同时更是如此）。
4. 地牢的出生格和梯子格会撞在同一格（出生格先算、梯子后放），导致玩家出生在梯子上、可达格数只剩 1。现在改成先放梯子、出生格避开梯子格。

**B. Unity 编辑器内的验证**：本机沙箱下 Unity 批处理模式不可用（UPM 与授权客户端的命名管道 IPC 连不上，报
`Could not connect to IPC stream "Upm-…"`、`Connection to channel LicenseClient-chair refused`、`Connectivity with IL Post Processor runner cannot be established yet.`），所以渲染/玩法需要在你自己的图形界面里跑：
1. 用 Unity Hub 打开工程 `C:\Users\chair\Desktop\vibe-gaming\DungeonCity`（会先自动编译脚本，等它跑完）；
2. 想先看结果：菜单 `DungeonCity → 全部自检…`，会在 `Docs\Generated\` 下写出矩阵文本和 4 张预览 PNG（城市/地牢的总览图与出生房间图；如果预览图整片是粉色，说明着色器没找到，脚本会直接报错）；
3. 想玩：先点一次菜单 `DungeonCity → 全部自检…`（它会创建并保存 `Assets\Scenes\Main.unity`、并写进 Build Settings），然后打开这个场景按 Play；
   也可以不用场景：`GameBootstrap` 用 `[RuntimeInitializeOnLoadMethod]` 自动启动，在任何空场景直接 Play 都会自动搭起城市并弹出主界面。
   主界面「开始游戏」→ 城市出生；走到梯子格切地牢；地牢里再走梯子格回城市。
