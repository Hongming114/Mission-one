## 4. 操作
| 操作 | 键 | 规则 |
| --- | --- | --- |
| 移动 | `W A S D` 或方向键 | 8 方向连续行走，2 格/秒（1 格 = 16 像素）；两键斜向、三键按剩下的单键、四键抵消 |
| 冲刺 | `Shift`（左右均可） | 0.5 秒冲 1.5 格，**冲刺过程中免疫伤害**，带残影；结束后 0.8 秒冷却 |

| 换房间 | 走到门格（III = 2.1） | 自动送到配对门的内侧，不会卡在门格里；穿门后有 0.25 秒冷却，不会来回传送 |

## 5. 玩法现状（按 `游戏项目设定\第一次\标准世界生成.txt` 实现）
- **世界**：I 类矩阵是房间的地图（数值 = 房间类型 1 城市 / 2 地牢），II 类是每格贴图（0 空 / 1 地板 / 2 墙 / 3 梯子），III 类是每格功能（0 不可达 / 1 可达 / 2.1 房间传送 / 2.2 跨世界）。房间尺寸、门配对、梯子唯一性、房内四连通、没有孤岛——都由 `Assets\Scripts\Gen\WorldValidator.cs` 校验。
- **出生**：城市出生房间的一个可站立格（不是门格、不是梯子格）；地牢出生点同理，两边都有一个梯子互通。
- **主角**：HP 100 / ATK 10；左上角血条 = **2 格宽**（按屏幕像素换算，随窗口大小变化），从右往左缩。
- **史莱姆**：0.8×0.8 格，HP 20 / ATK 5；视野 4 格内追击（沿房间路径寻路，能穿门跨房间），视野外原地待机；与主角**间隙 ≤ 0.5 格**时开始蓄力，**1 秒后扑击**（0.4 秒、4 格/秒）命中 -5 HP，之后 0.8 秒冷却；与主角、与其它史莱姆都不会重合（碰撞体积会被推开）。
- **受击规则**：主角打中史莱姆 → **终止它当前攻击动作**（蓄力/扑击被打断）+ **变红** + **沿远离主角方向击退 0.5 格** + 掉主角的伤害值（10）。
- **刷怪**：每 60 秒判定一次；场上怪 ≤ 2 只时改为每 5 秒（有最小间隔）；在"距玩家所在房间 ≥ 2 个房间距离"的房间里按每房 10% 抽样格、每格概率 P 出怪；上限 = 2 × 房间数。整套规则在 `Assets\Scripts\Gen\MonsterSpawnPlanner.cs` / `MonsterSpawnDirector.cs`，干跑结果见 `Docs\Generated\自检报告.txt`。
- **死亡**：HP 归零 → 回当前世界出生点并回满血（左上角血条与 HUD 面板都会记录重生次数）。

## 9. 补充说明（后加）：调试键细节 + 梯子设定 + 暂不实现的设定

### 9.1 三个调试键到底做什么
都在 `Assets\Scripts\Game\GameBootstrap.cs` 的 `Update()` 里判定，**只在点了「开始游戏」之后生效**（`started == true`），都是 `Input.GetKeyDown`（按一下触发一次）。

**`V` — 直接切到另一个世界的出生房间（纯调试传送）**
- 城市 → 地牢、地牢 → 城市；落点是**那个世界的出生房间出生格**（不是梯子旁）。
- 切换时做的事与走梯子完全一样（走同一个 `GameSession.SwitchWorld`）：旧世界视图隐藏、新世界视图显示（第一次去时现建）、主角放到落点（格子中心 + 朝房间中心退 0.6 格）、`portalCooldown = 0.3s`、刷怪计时归零、`ladderArmed = false` + `ladderCooldown = 0.6s`。
- 用途：不用跑图就能看另一个世界。它**不改变游戏进度**：不刷怪、不掉血、不清怪。
- 调试面板"最近事件"显示：`调试：切换到城市/地牢（M=1/2）的出生房间`。

**`R` — 回到城市出生点并回满血（保底/复位）**
- 无论当前在哪个世界，都切换回**城市**出生房间的出生格，并把 HP 恢复满（`player.RestoreFull()`）。
- 用途：血量见底、掉进怪堆、卡在半路时保底重来。
- 注意：**R 键不会让"重生次数"增加**；只有 HP 归零时自动复活（`Respawn()`）才会 +1。提示为 `调试：回到城市出生点`。

**`F1` — 开关左上角调试面板**
- 只是显隐（`SetActive`），不影响玩法；面板每 **0.2 秒**刷新一次，所以数字是跳着变的。
- 面板内容：世界（城市/地牢，M = 1/2）与种子、I 类矩阵尺寸与房间数；当前房间坐标（在房间之间空隙里时显示"（在两房间之间的空隙里）"）；玩家所在世界格、房间内局部格、II 类贴图值、III 类功能值；朝向（含 8 方向贴图序号）；`HP 当前/上限`、ATK、状态（冲刺中（免疫伤害）・挥剑中 x%・受击闪红・阵亡・正常）；冲刺次数与冷却剩余、挥剑/命中/被扑击/击杀次数；房间距离统计（最近/最远/平均/≥2 房间数）；刷怪判定次数与距下次判定倒计时、最近一次判定结果、场上史莱姆数量/上限/死亡次数；最近一只史莱姆的 HP、状态、与主角圆心距、间隙；最近事件；操作提示。

### 9.2 梯子（III = 2.2）的完整设定
- **触发方式**：踩上去就切，不需要按键、没有交互提示。
- **判定**：主角**脚下中心所在格**的 III 值为 2.2 就切换世界（`GameSession.HandleLadder`：`FuncCode.IsWorldPortal(map.FuncAt(PlayerWorldCell))`）。
- **数量与配对**：每个世界正好 1 个梯子格（`WorldValidator` 校验），两个世界的梯子在 I 类矩阵的**同一格**，所以两边都能上/下。
- **防连跳三重保护**：(1) `ladderArmed`——必须离开梯子格才会重新武装；(2) 切换后 `ladderCooldown = 0.6s`（踩到梯子时设 0.8s）；(3) 落点 = 梯子格中心 + 朝房间中心退 0.6 格（`ArrivalPos`），不会正好站在梯子格上；另加 `player.portalCooldown = 0.3s`。
- **切换时同时发生**：旧世界视图隐藏、新世界视图显示（首次访问现建并缓存）、主角外观立即刷新（`ApplyVisualImmediate()`）、刷怪计时归零（`monsterDirector.ResetTimer()`）；切到地牢时记录 `lastDungeonPlayerRoom`（城市里的刷怪判定要用"玩家上次在地牢的房间"）。
- **对史莱姆**：梯子格对怪是**墙**（`WalkMap.IsWalkable(cell, forPlayer: false)` 把 `FuncCode.WorldPortal` 也算阻挡），所以怪不会跟着换世界；史莱姆只在地牢生成。
- **换世界不清场**：史莱姆留在自己所属世界继续存在（`SlimeSim.worldKind` 记住来源）；主角在城市时怪原地待机（`Tick` 收到 `player = null`），主角在地牢时剑只打 `worldKind == currentKind` 的怪。
- **和门（III = 2.1）的区别**：门是**同一世界内房间之间**的传送（成对门、0.25s 冷却、落点朝房间中心退 0.6 格）；梯子是**世界之间**的传送（成对梯子、0.6~0.8s 冷却）。
- **以后想改成按键交互**：只要在 `Assets\Scripts\Game\GameSession.cs` 的 `HandleLadder` 里加一个"按键按下"的条件（例如给 `Tick` 多传一个 `bool interactRequested`），其余（落点、冷却、视图切换）都不用动。目前保持"踩上去就切"。

### 9.4 自检结果会落盘成一个文件（我不用开 Unity 也能读到）

**（2026-10-11 追加；对应"路线 3：把 Console 输出落盘"。本节只追加，上文一字未改。）**

**一句话**：在 Unity 里点任何一个 `DungeonCity/...` 自检菜单，跑完都会在 `Docs\Generated\Unity自检结果.txt` 留下一个文件，内容是"做了哪几步 / 哪步失败 / 产物在哪 / 完整 Console 输出"。把这一个文件给我，我就能判断这次自检发生了什么。

**文件结构**（由 `Assets\Editor\ProjectSetup.cs` 里的 `RunCapture` / `OnLogMessage` / `WriteCaptureResult` 生成，UTF-8 无 BOM）：

1. 头部：时间、`Application.unityVersion`、工程路径、是否批处理模式（`-batchmode` 下是 `True`）。
2. `## 步骤清单`：每一步一行 `[通过] / [失败] 步骤名 —— 失败原因`。
3. `## 结论`：`全部通过 ✅` 或 `存在问题 ❌（错误 n 条 / 警告 m 条）`。

### 9.5 两条补记（2026-10-11 再追加）

- **`使用的 shader = (未找到)` 是日志顺序问题，不是真找不到 shader**：`MaterialLibrary` 是懒加载（第一次创建材质时才 `Shader.Find`），而原来那行日志在创建材质之前打印，所以打出的是初始值。现已改成先取一次 `MaterialLibrary.BaseShader` 再打印；真实结果是 `使用的 shader = Standard（Standard）`。
- **桩试跑不会再覆盖真实预览图**：`3. 渲染预览 PNG` 写文件前会判断 `EncodeToPNG()` 结果是否为空，为空只记一条警告、不写文件（桩环境没有真实渲染，编码结果为空）。所以用 `Tools\EditorSmokeTest` 跑冒烟测试不会再动 `Docs\Generated\*_世界总览.png` 与 `*_出生房间.png`。要真正的预览图：在图形界面点 `DungeonCity/3. 渲染预览 PNG`，或重跑 9.4 里那条批处理命令。

## 9.6 文档反馈（「以下是更改：」八条）实现说明

来源：`游戏项目设定\第一次\标准世界生成.txt` 第 43 行起的八条反馈。

### 1. 视角放大到 175%
- `Assets\Scripts\View\CameraRig.cs`：`orthoSize = 11f / 1.75f ≈ 6.29`（原来 11）。视野变小、角色看起来更大。

### 2. 松开方向键就停
- `Assets\Scripts\Sim\PlayerSim.cs`：位移只认"本帧的输入"，松手当帧速度归零（原来是按住上次的 `inputDir` 继续走）。

### 9.10.1 反馈与现象

用户（附两张 Play 截图）：「这种情况应该允许遮挡，即玩家在墙等遮挡物的上方时」。

调试3-6 为了消除"角色身上一条横线"的观感，把精灵材质换成了 `DungeonCity/SpriteAlways`（`ZTest Always`）——横线没了，但代价是**精灵完全不再参与深度遮挡**：玩家站在墙的北侧、墙位于相机与玩家之间时，墙也不会挡住玩家的下半身，看起来像"贴着墙面浮在上面"。

### 9.10.2 根因与修法（顶点高度剪切）

相机是正交、俯角 52°、yaw 0，于是 `forward=(0,-0.788,0.616)`、`up=(0,0.616,0.788)`：

- 屏幕纵坐标 `σ = 0.616y + 0.788z`；相机深度 `d = -0.788y + 0.616z`。
- **有高度的几何体（墙顶面）因为 `-0.788y` 项"天然更靠近相机"**，所以只要它在屏幕投影上碰到角色，就会在角色身上切出一条横线（这就是 9.9.6 的根因，横线相对脚底的高度 ≈ `0.616×墙高 − 0.788×距离`）。

修法（`Assets\Scripts\Core\ViewShear.cs`，由 `Assets\Scripts\View\MeshBuilder.cs` 的 `AddQuad` 对每个顶点应用）：

`v' = v + forward × (sin(pitch) × v.y)`，52° 时为 `(x, 0.379y, z + 0.485y)`。

因为**正交投影下沿视线方向平移不改变屏幕位置**，所以画面与修改前完全一致；但深度变成 `d' = 0.616z`（只与水平位置有关）→ 遮挡关系等于**地图前后关系**：

- 墙在南侧（相机与玩家之间）→ 会遮住玩家下半身（本次反馈要的效果）
- 墙在北侧（玩家身后）→ 永远在玩家之后，不会在角色身上切横线（9.9.6 要的效果）

同时撤销 9.9.6 的 shader 方案：删除 `Assets/Shaders/SpriteAlways.shader`（含 .meta 与空目录），`SpriteLibrary.ShaderCandidates` 恢复为 `Sprites/Default …`（`ZWrite Off` + `ZTest LEqual`），精灵重新参与深度测试。

配套：冲刺残影的抬升改到**相机平面内**（`cam.transform.up × AirHeight`，见 `PlayerView.UpdateDashGhosts`）——直接抬 y 会减小深度，跳跃冲刺时残影可能穿到墙前面。

### 9.10.3 验证与限制

台架 `DungeonCity\Tools\LogicCheck`（第 12 节）对剪切公式做了断言：屏幕位置不变（误差 < 1e-4）、深度 = `cos(pitch) × z`、南墙的顶面在玩家之前（允许遮挡）、北墙的顶面在玩家之后（不切角色）、墙顶面深度与同格地面相同。三套台架：`Tools\CompileCheck` 0 错误；`Tools\LogicCheck` 通过 114 / 失败 0（`Docs\Generated\台架输出.txt`）；`Tools\EditorSmokeTest` 六步全通过。

限制：剪切只作用于**环境网格**（地板/墙/碎石/门/梯子），精灵仍按逻辑坐标绘制（深度 ≈ `0.616z`），两者一致；墙也不能再遮挡"比它更南"的东西（那本来也不该被挡住）。渲染观感请在 Unity 里 Play 复核：贴着墙走一圈，墙在身前应挡住下半身，墙在身后不应在角色身上切横线。
